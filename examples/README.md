# Примеры

## Откуда данные

Работодатель дал YML-фид каталога (`https://www.souz-pribor.ru/yml/any/feed.xml`) с предложением
выбрать любые два товара. Разбор фида на 03.11.2026:

- 22 353 товара, все с `available="true"`;
- **ни у одного нет описания и технических характеристик** — в `<param>` только «Артикул» и «Код товара»;
- манометров в фиде нет, хотя на сайте такая категория есть.

Поэтому из фида взяты название, тип, производитель, категория и ссылка, а характеристики
и описание — со страниц этих товаров на souz-pribor.ru (ссылка в поле `source_url` каждого файла).
Цены, наличие, отзывы и гарантийные условия во входные данные не включены.

## Товары

**[testo-830-t1.json](input/testo-830-t1.json)** — пирометр testo 830-T1 (Testo), id в фиде 64423.
Простой случай: у товара один вариант, страница полностью описывает именно его.
Из блока «Особенности» на странице добавлены характеристики «Оптическое разрешение: 10:1»,
«Коэффициент эмиссии» и «Лазерный целеуказатель».

**[owen-pd100-di1.6-111-0.5.json](input/owen-pd100-di1.6-111-0.5.json)** — датчик давления ОВЕН
ПД100-ДИ1,6-111-0,5, код товара 65316. Сложный случай: страница общая для 114 модификаций серии.
Значения конкретной модификации (верхний предел 1,6 МПа, резьба штуцера М20х1,5, класс точности
0,5 %) взяты из таблицы модификаций на той же странице, общие характеристики — из таблицы серии.
Строки серии, где перечислены варианты для всех модификаций («0,5; 1,0 % ВПИ», «M20х1,5;
опционально G1/2"; G1/4"»), заменены значениями модификации. Описание оставлено как есть —
оно про всю серию, и промпт отдельно запрещает выдавать диапазоны серии за характеристики товара.

**[manometer-dm02-from-task.json](input/manometer-dm02-from-task.json)** — пример из текста задания
без изменений. Показывает работу с неполными данными: описание обрезано на «...», для манометра
не хватает степени защиты. Данных мало, поэтому SEO-описание намеренно короче 800 символов
и помечено предупреждением — вместо «воды», которой модель добивала объём в первых прогонах.

## Ошибки в данных сайта, найденные при подготовке

На странице ОВЕН ПД100 модели 1х1:

1. В таблице характеристик строка «Атмосферное давление рабочее: от 16 кПа до 40 МПа» — это диапазон
   верхних пределов измерения, а не атмосферное давление. Во входные данные не включена.
2. Строка «Устойчивость к механическим воздействиям» разбита на две ячейки
   («группа исполнения V3» / «по ГОСТ Р 52931»). Во входных данных объединена.
3. У модификации ПД100-ДИ1,6-181-0,5 в таблице модификаций указана резьба G1/2,
   хотя у остальных модификаций модели 181 — G1/4.

Сервис такие ошибки не исправляет (он доверяет входу), но это хороший кандидат на следующую
функцию: проверку согласованности данных до генерации — см. docs/DECISIONS.md.

## Результаты и вычитка

[output/](output) — карточки, полученные сервисом на реальной модели: `openai/gpt-4o-mini`
через OpenRouter, промпт версии 3 (`meta.prompt_version`). Тексты **не правились вручную** —
это ровно то, что сервис выдаёт контент-менеджеру.

| Товар | Статус | Попыток | Заголовок | Описание |
|---|---|---|---|---|
| testo 830-T1 | `ok` | 2 | 36 симв. | 1121 симв. |
| ПД100-ДИ1,6-111-0,5 | `ok` | 2 | 49 симв. | 1113 симв. |
| Манометр DM 02 (из ТЗ) | `needs_review` | 1 | 38 симв. | 440 симв. — мало данных, см. предупреждение |

«Попыток: 2» — проверки нашли проблему в первом ответе, и модель её исправила.
Выдуманных чисел и технических кодов нет ни в одной карточке.

Ручная вычитка нашла то, что автоматические проверки не ловят. Это ожидаемо: результат
сервиса — черновик для человека, а не готовая карточка.

1. **ПД100: «Корпус датчика выполнен из нержавеющей стали AISI 316L».** Во входных данных
   из этой стали сделана мембрана, материал корпуса не указан. Свойство части перенесено
   на весь прибор — смысловое искажение без новых чисел и кодов, фактчекеру не видно.
2. **Манометр: «обеспечивает достаточную точность для большинства промышленных задач».**
   Оценка, которой нет в данных; в словарь оценочных слов такие обороты не попадают.
3. **testo: запрос «пирометр -30 … +400 °c»** — так в поиске не набирают.

Все три — довод за второй проход «LLM-судьёй», который сверяет каждое утверждение текста
с входными данными (улучшение 4 в [docs/DECISIONS.md](../docs/DECISIONS.md)).

## Граничные случаи

[edge-cases/](edge-cases) — для проверки обработки ошибок, например:

```bash
python -m kip_card check examples/edge-cases/*.json
```

- `broken-syntax.json` — некорректный JSON: сообщение с номером строки и столбца;
- `no-name.json` — нет названия: карточку собрать нельзя, ошибка;
- `empty-fields.json` — пустой производитель, описание и характеристики: карточка собирается,
  всё отсутствующее помечено «данных нет», статус `needs_review`.
